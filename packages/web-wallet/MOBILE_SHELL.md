# Phone shell

At viewport widths up to 640px, Home uses a compact account, notification, search-toggle and menu row. Opening search focuses the existing `TagSearchBar` beneath that row. Escape closes it and returns focus to its toggle. Search lookup, contact verification and navigation use the existing contacts implementation.

This is an inferred composition of the identity/bell/menu Home and search-field Home references. The Menu reference retains primary navigation. The Home and Menu reference screenshots are 402×879; their measured wallet content region is 402×678 (Home begins at y=123; Menu at y=124). Browser controls are outside the app. Runtime sizing never subtracts their height. Design review of this composition remains pending.

## Page interfaces

`usePhoneLayout()` matches the ordinary 640px CSS media queries. `SidebarLayout` accepts `mobilePageHeaderPaths?: readonly string[]`, defaulting to an empty list so every route retains shell navigation. ULT-783 opts in with `<SidebarLayout mobilePageHeaderPaths={["/contacts"]} />` when its Contacts back/title row and search field are present. Matching uses the exact pathname; contact detail routes retain the shell header. Locked sessions retain the brand lockup and menu because the guarded page cannot render its header until unlock. Desktop retains the global top bar. `useShellActions()` exposes `openMenu()` and `openShareTag()` to page-owned controls. Scan controls remain absent until the scanner is implemented.

Opting into a page header also unmounts the shell notification bell and its transient toast queue on that phone route. Persisted notifications remain available through the bell on other routes. The Contacts page owns its back/title and search controls; its final notification access and Share origin/focus behavior are coordinated with ULT-783 and ULT-785.

`TagSearchBar` accepts optional `autoFocus` and `onDismiss` props; `onDismiss` handles Escape. The phone shell mounts one search field while expanded. Keyboard focus moving to another element outside the field and results dismisses the results. A blur with no focus target keeps results mounted so Safari can deliver a result tap; outside pointer interactions still dismiss them. Search results retain their existing lookup and save state.

The phone `.ww-main` and `.ww-content` have a minimum height of `100dvh` and grow with their content. `.ww-content` is a column flex container; `.ww-shell-header` has its intrinsic height and does not shrink. Routed pages are direct flex children and can use `flex: 1` for remaining space. There is no header-height subtraction. The outer content owns the top, left, right and bottom safe-area tokens once. Flow-specific panels must preserve that sizing and choose their own internal scroll ownership.

## Overlays and navigation

The phone menu uses a native modal dialog. The browser contains focus and makes the page behind it inert. Opening the menu focuses Close menu, closes search and notifications, and locks document scrolling. Escape, Close menu, backdrop activation, route changes and crossing the phone breakpoint release it. Dismissal preserves focus requested by the destination page, otherwise restoring the opener when it is still visible; a resize to desktop falls back to the active navigation item. The fixed menu applies all four safe-area tokens and scrolls to Settings and Logout on short viewports.

Share and Logout close the menu before mounting their existing modal. Phone identity, notifications and search use the same unlock condition as the guarded page. Locking clears expanded phone search. Closing notifications through the shell marks them read. Primary destinations remain available through the menu. Desktop navigation stays visible. Between 641px and 960px, a narrower sidebar and wrapping top bar keep Home and search usable.

Home retains its balance source, four payment actions, incoming requests, transaction and Pending tabs, View all route, and registration/recovery notices. Phone Home omits the desktop promotional rail: Invite friends, iOS app release, the duplicate paylink card and the duplicate Share card. Registration, secure-name and recovery notices remain before Home; incoming requests keep their existing order. Paylink creation remains available through Send and identity sharing through menu Share @tag. Long content scrolls with the page. Desktop promotional cards are unchanged.

Inbound paylinks use the current `useClaimLinkFlow().modal` contract on phone and desktop, independently of the promotional rail. Decline dismisses the prompt and clears its stash. Accept keeps the claim sheet open through the signing interaction; successful signing closes it and opens Notifications, whose progress row carries the remaining operation and its result. Failed signing keeps the sheet open. A claim that needs no signing closes the sheet and opens Notifications when it succeeds. Home does not render the removed claim reminder toast or insert a synthetic claim row into its activity feed.

## Web Figma phone fidelity

Phone Home and menu payment actions follow Deposit, Receive, Send, Withdraw. Desktop keeps its existing order. The phone menu uses the web Menu frame's 40px horizontal insets, top separator, 24px group spacing, 52px rows and 24px glyphs. The shared phone header keeps the combined identity, Notifications, expandable Search and Menu interaction; its identity pill uses the web reference border and spacing. Search and Menu keep 40px circles around 30px glyphs, compared with the two 50px circles in the web Home reference; Notifications uses a 24px glyph in a 40px circle. These sizes preserve the retained combined-header interaction and still require design review. The balance-hidden state retains the existing design-system eye-off glyph because no matching web Figma export was supplied.

`PhoneIcon` from `src/ui/PhoneIcon.tsx` is opt-in. Its props are `name: PhoneIconName`, `size?: number` (default 24), `color?: string` (default currentColor) and `className?: string`. It renders a decorative CSS mask from the original monochrome web Figma SVG; the calling control owns its accessible name. Names are `home`, `person`, `coins`, `arrow-down`, `send`, `tray-withdraw`, `history-clock`, `settings`, `logout`, `qr-code`, `x`, `search`, `menu`, `arrow-left`, `search-field`, `scan`, `chevron-right`, `copy`, `share-forward`, `bell`, `eye` and `flashlight`. Asset hashes and web Figma node IDs are in `src/assets/phone/provenance.json`. Design-system Icon, TopNavIconButton and shared Modal defaults are unchanged. Contacts, Share and Scanner opt in in their owning layers.

Only exact phone Home receives `.ww-shell--home`. Its gradient preserves the existing web SVG's intrinsic dimensions and uses the web Figma circle position; other route backgrounds are unaffected. Its content uses 24px side insets, 50px balance text, 32px action glyphs and the original web deposit illustration layers. The layout grows with notices and long content rather than subtracting a fixed header height.

When the menu brand and action group do not fit within the 40px insets plus safe areas, the complete action group wraps to a second row aligned to the trailing edge, with a 16px row gap. Fitting two- and three-control headers retain their reference geometry. The 390px header with 12px side safe areas has 286px available, less than the three-control row's 297px minimum. Large balance strings use smaller phone text after twelve formatted characters; unusually long values can still wrap to preserve every digit.

The phone coin illustration is a 523,744-byte lossless WebP derived from the original 1402×1122 web Figma PNG at unchanged dimensions. `provenance.json` retains the original PNG hash and conversion parameters. All decoded RGBA bytes, including transparent pixels, match the original. The image decodes asynchronously and keeps the same percentage crop.
