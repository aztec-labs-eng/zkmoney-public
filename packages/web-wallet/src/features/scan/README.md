# Scanner surface

`ScannerModal` is a phone surface. Its parent must mount it only for an unlocked, registered wallet on a phone layout, and must exclude the desktop launcher while its camera policy denies access. Unmount it when any guard stops holding.

The parent supplies `resolvePayload` using the shared `scanPayload` adapter and the current identity. Camera frames and the manual form use the same resolver and one successful handoff per mount. `onDestination` receives the existing route and optional navigation state; the parent closes the overlay and performs navigation after capture has stopped. Close remains available if that unmount is delayed; the parent should preserve destination focus when handling this late close. An invalid payload leaves the camera stopped until the user chooses Try camera again. The video stays mounted below every loading, error and paste state so retry can start a new session.

`onClose` and optional `onShare` run after synchronous camera cleanup and disposal of pending handoffs. Omit `onShare` to hide that action. The parent owns the underlying route, initial overlay, reciprocal Scan/Share transitions, and viable destination or origin focus. Remount each overlay when switching; toggles should not add browser history entries.

The surface consumes the shared `Modal` public props: `variant="bare"`, `className`, `label` and `onClose`. Its scoped CSS requires `.ww-modal-overlay > .ww-modal.ww-scan`, with the scanner child owning safe-area padding and scrolling. The native dialog retains that direct-child structure. After transient controls disappear, focus may recover to the scanner card or Close; Tab from the card must reach Close and stay contained. Destination focus takes priority over an old opener. `useScanShare` owns the initial surface and opener; Close from the reciprocal surface returns to that initial surface, and Close there dismisses it. `ScanNavigationProvider` remains mounted above the shell so `/link` and `/request` can receive focus after replacing the shell.

Run component tests with `pnpm test test/scannerModal.test.tsx` from `packages/web-wallet`. The explicit `pnpm test:ui-capture` browser suite includes the isolated surface proof. To run only that proof, use `PLAYWRIGHT_BROWSERS_PATH=/path/to/browser-cache pnpm exec node --test scripts/ui-capture/test/scanner-surface.test.mjs`. It uses the real camera hook, bundled worker and controlled canvas streams, with fixture payload resolution and a fixture Share endpoint. Its screenshots and report are written to a fresh `/tmp/ult-785-isolated-surface-*` directory. Reduced CSS viewport height checks scrolling; physical keyboard, toolbar, camera and deployed policy remain separate acceptance gates. See the [integrated scanner plans](../../../scripts/ui-capture/plans/scan/README.md) for real App transitions and production worker verification.

Phone Contacts exposes one `Scan QR code` button after `Search @tag`; it has no header Share button. Close returns to the invoking Scan control, while a successful unsaved-tag handoff focuses Search. Share remains available from the menu and the scanner reciprocal control. The scanner uses the supplied web QR and flashlight assets. Close uses the web menu x asset; the Scan reference contains a text symbol rather than an exported SVG, so this is not an exact Scan-symbol export. Viewfinder and manual-form layout are unchanged.
